

### 1. Valid object (baseline case)

**Purpose:** Verify that untampered objects are accepted.

**Checks**

* No false positives.
* Normal read succeeds.

**Backend:** FS.

**How**

* Write an object through SecureDAL.
* Read it through SecureDAL.
* Verification should succeed.

---

### 2. Object without anchor

**Purpose:** Verify that objects not managed by SecureDAL are rejected.

**Checks**

* Missing integrity anchor is detected.

**Backend:** FS.

**How**

* Use a standard OpenDAL operator (or backend directly) to write an object.
* Attempt to read it through SecureDAL.
* Verification should fail because no anchor exists.

---

### 3. Object content tampering

**Purpose:** Verify integrity protection of stored data.

**Checks**

* Modified object content is detected.

**Backend:** FS.

**How**

* Write through SecureDAL.
* Modify the stored object directly using OpenDAL (or backend tools).
* Read through SecureDAL.
* Verification should fail.

---

### 4. Multiple tampered objects

**Purpose:** Verify batch verification.

**Checks**

* `read_all()` detects tampered objects.
* Detection works regardless of which object was modified.

**Backend:** FS.

**How**

* Write several objects.
* Tamper with one or more.
* Execute `read_all()`.
* Verification should report the tampered objects.

---

### 5. Deleted object

**Purpose:** Verify detection of unauthorized deletion.

**Checks**

* Object removal cannot be hidden.

**Backend:** FS.

**How**

* Write through SecureDAL.
* Delete the object from storage through OpenDAL (or backend) directly.
* Attempt to read.
* Verification should fail.

---

### 6. Anchor deletion

**Purpose:** Verify integrity anchor protection.

**Checks**

* Missing anchor is detected.

**Backend:** FS.

**How**

* Write through SecureDAL.
* Remove the local anchor record (unpin + garbage collection).
* Read through SecureDAL.
* Verification should fail.


---

### 7. Pinned-anchor recovery

**Purpose:** Verify resilience when local anchors are lost or corrupted.

**Checks**

* Recovery from IPFS/Pinata works correctly.

**Backend:** FS.

**How**

* Write object with Pinata pinning enabled.
* Remove the local anchor.
* Read through SecureDAL.
* Prototype retrieves anchor from IPFS peers.
* Verification succeeds.

---

### 8. Anchor Injection Attack

**Purpose:** Verify that an attacker cannot create valid integrity records outside SecureDAL.

**Checks**

* Objects not managed by SecureDAL are rejected, even when a matching anchor exists.
* Verification depends on the integrity anchor generated by SecureDAL, not only on the object hash.

**Backend:** FS.

**How**

* Create or modify an object directly through a standard OpenDAL operator.
* Compute the hash of the object content.
* Manually create and store a corresponding anchor in IPFS.
* Read the object through SecureDAL.
* Verification should fail.

---

### 9. Rollback attack

**Purpose:** Verify detection of reverting object state.

**Checks**

* Previous object versions cannot be silently restored.

**Backend:** FS.

**How**

* Write version A.
* Update to version B.
* Restore version A directly through a standard OpenDAL operator.
* Read through SecureDAL.
* Verification should fail.

---
